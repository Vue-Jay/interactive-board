OnlineRepetitor v80 — жизненный цикл корзины

Сделано:
- исправлен старый лимит ручного удаления: Storage теперь листается страницами по 1000 объектов;
- сервер ежедневно находит доски, лежащие в корзине 30+ дней;
- добавлена безопасная очередь board_purge_queue;
- доски без Storage-файлов автоматически удаляются из БД;
- доски с оставшимися файлами НЕ удаляются из БД вслепую: остаются в очереди, чтобы не создавать сиротские файлы;
- в корзине видно состояние очереди и число оставшихся файлов;
- обычный authenticated-клиент не может запускать purge-функции;
- pg_cron выполняет серверную проверку ежедневно.

Важно: удалять бинарные объекты Supabase Storage прямым DELETE из storage.objects нельзя. Поэтому полностью автоматическое удаление доски с файлами требует серверного Storage worker/service-role. v80 намеренно выбирает безопасный вариант: не удаляет запись доски, пока файлы физически не очищены.

Порядок:
node install_v80.mjs
В Supabase SQL Editor выполнить supabase/v80_trash_lifecycle.sql
npm run build

После успешной проверки:
git add .
git commit -m "v80: automate safe trash lifecycle"
git push
